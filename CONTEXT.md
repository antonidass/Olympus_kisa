# Контекст проекта: Кисы Олимпа

Полный пайплайн создания коротких анимированных роликов по греческим мифам для канала «Кисы Олимпа»: сценарий → промпты → картинки → видео → озвучка → монтаж.

Этот файл — единственная точка входа в проект. Спецификация монтажа вынесена в отдельный [CAPCUT.md](CAPCUT.md) (источник правды по стилям, переходам, SFX и шрифтам). Всё остальное — здесь.

## О канале

- **Название:** Кисы Олимпа
- **Платформы:** YouTube Shorts, TikTok, Instagram Reels
- **Тематика:** Короткие видео (до 1 минуты) по древнегреческим мифам — боги Олимпа, герои, мифические существа
- **Визуальный стиль:** Пиксель-арт. Все персонажи — пиксельные котики в древнегреческих образах

## Установка

```bash
# Автоматизация (Python)
cd "BOGI AI"
pip install -r automation/requirements.txt
python -m playwright install chromium

# pyCapCut (Python) — монтаж в CapCut-драфт
pip install -r pyCapCut/requirements.txt
```

Также нужен **ffmpeg** в PATH (используется webapp для склейки превью озвучки и cosyvoice_runner для конвертации). Скачать с [ffmpeg.org](https://www.ffmpeg.org/download.html#build-windows), распаковать и добавить `ffmpeg.exe` в системный PATH.

Шрифты эталона Персефоны (`STRomeTrial-Bold.otf`, `Anticva-Regular.otf`) лежат в `assets/fonts/` — установить в Windows двойным кликом → «Установить», иначе CapCut молча подменит на системный и вёрстка караоке/интро поплывёт.

## Создание сценария через UI

В webapp в шапке списка мифов есть кнопка **«+ новый»**. Клик → модалка с полем имени → бэкенд `POST /api/scenarios/create` создаёт всю папочную структуру и три заготовки промптов:

```
content/<Название мифа>/
├── prompts/
│   ├── voiceover.md        # шаблон: кликбейтный хук → интро → основной текст
│   ├── images.md           # шаблон с правилами канала и Сценой 1
│   └── video.md            # шаблон с обязательным негативом
│   # stickers.md создаётся Claude'ом на шаге 8 (не входит в scaffold)
├── voiceover/
│   ├── audio/              # пусто — заполнится при генерации TTS
│   └── texts/              # пусто — сюда кладутся sentence_NNN.txt
├── images/
│   ├── review_images/      # пусто — сюда кладутся scene_NN/vN.jpg
│   ├── approved_images/    # пусто — сюда переезжают аппрувнутые после ревью
│   └── stickers/           # пусто — сюда `distribute_stickers.py` кладёт scene_NN_<маркер>.jpeg
├── video/                  # пусто — сюда кладутся scene_NN_M.mp4
├── music/                  # пусто — фоновый трек кладётся вручную
└── final/                  # пусто — сюда CapCut экспортирует финал
```

После этого миф появляется в хабе со статусом «wip» (текста ещё нет). Дальше — обычный пайплайн: пишется текст в `voiceover.md`, разбивается на `voiceover/texts/sentence_NNN.txt`, генерируется озвучка и т.д.

**Имя папки = точное название мифа на русском, с заглавных букв, через пробел, без подчёркиваний.** То же имя используется для финального видеофайла.

Программный аналог (без UI) — `python webapp/app.py` запустить и руками POST'нуть, либо просто `mkdir`-ом, но через UI быстрее и заведомо без ошибок в структуре.

## Пайплайн создания ролика

1. Предложить 5 сценариев. Я выбираю один.
2. **Сразу же раскатать структуру нового мифа скриптом:**

   ```bash
   python automation/create_scenario.py "<Название мифа>"
   ```

   Скрипт создаёт `content/<Название мифа>/` со всеми подпапками (`prompts/`, `voiceover/audio`, `voiceover/texts`, `images/`, `video/`, `music/`, `final/`) и тремя шаблонами промптов (`voiceover.md` с порядком «хук → титул → текст», `images.md` и `video.md` с правилами канала и обязательными негативами). Это предусловие для всех следующих шагов — без папок webapp не покажет миф в хабе, раннеры не найдут куда писать. Если сценарий уже существует — скрипт падает с понятной ошибкой и ничего не трогает.

   Альтернатива — кнопка **«+ новый»** в webapp (та же логика, общий модуль `automation/scenario_scaffold.py`). Ручной `mkdir` тоже работает, но через скрипт быстрее и заведомо без опечаток в структуре.
3. Далее пишется сценарий по выбранному мифу и вместе с ударениями отправляется мне на проверку. **Структура voiceover.md жёсткая:** `# Заголовок` → **кликбейтный хук в 1–2 предложения** (sentence_001, удерживает зрителя в первые 3 секунды, эталон — Персефона и Аид) → `<Имя>. Миф за минуту.` (sentence_002, титул) → основной текст истории. Хук и титул **монтируются как одна сцена** (картинка-крючок + накапливающийся караоке-титул поверх). Подробности и шаблоны хуков — ниже в разделе «Кликбейтный хук ДО интро».
4. После правок текст попадает в `content/<Название мифа>/prompts/voiceover.md`
5. Далее надо разбить текст на предложения и положить в папку voiceover/texts (как например для сценария Персефона и Аид)
6. Далее открывается веб приложение для ревью озвучки. Я нажимаю на кнопку сгенерировать озвучку для текущего сценария. Жду. Выбираю озвучки. Если надо перегенерирую.
7. Далее пишутся промпты картинок (`prompts/images.md`), я даю апрув на эти промпты и если все ок то я запускаю сам в гугл хроме Flow и используя расширение с промптами сам генерирую картинки а потом скачиваю архив и далее скрипт подхватывает и распаковывает картинки из архива и распределяет их по сценам:
   **Ручная генерация в Flow + `distribute_images.py`:**
   Если предпочитаешь работать в Flow руками (видеть варианты в UI, перегенерить отдельные сцены, редактировать промпт на лету), можно сгенерить все картинки вручную, скачать всё одним «Download all» и разложить через `automation/distribute_images.py`:

   ```bash
   # 1. Сухой прогон — план раскладки + подсказки по позиции для спорных префиксов
   python automation/distribute_images.py "content/<миф>/images/<archive>.zip"

   # 2. Скопировать готовую --map команду из вывода, проверить визуально, добавить --execute
   python automation/distribute_images.py "content/<миф>/images/<archive>.zip" --execute \
     --map "withered_wheat_field=15" --map "demeter_in_frozen=27" ...
   ```

   Как скрипт сопоставляет файлы со сценами:
   - **`✓` строгий префикс** — имя файла начинается с тех же слов что маркер сцены (Flow обычно так и делает). Это требует чтобы первое слово маркера было уникальным — см. правило выше.
   - **`~` Flow обрезал маркер** — иногда Flow съедает 1-е слово (`meadow earth chasm bursting` → `Earth_chasm_bursting`). Substring-matcher это закрывает.
   - **`?` fuzzy** (`--fuzzy`) — пересечение слов как множеств. Используется когда в Flow редактировался промпт (`Hades_abducting_Persephone` ≠ `hades scooping persephone meadow`). **Ненадёжно — обязательно сверить визуально перед `--execute`.**
   - **Подсказка по позиции в архиве** — для несопоставленных префиксов скрипт смотрит на их порядок в zip-архиве (Flow сохраняет порядок генерации) и предлагает сцену между ближайшими «якорями» уже сопоставленных. Если генеришь сцены строго по порядку — работает почти всегда.
   - **`--map "prefix=scene_num"`** — ручной override для тех случаев когда автомат не справился. Можно повторять флаг сколько нужно.

   Скрипт безопасен: dry-run по умолчанию (без `--execute` ничего не двигает), останавливается если есть несопоставленные файлы (не делает частичную раскладку), пишет каждую операцию `mv` в лог. Распакованный `_unpacked/` удаляется автоматически после успешной раскладки.

   **Обязательное ревью промптов перед генерацией картинок (защита от «пропавших» волос/одежды):**
   После того как написал все `**Промпт:**` в `prompts/images.md` — пройтись по КАЖДОМУ промпту глазами и сверить с КАРТОЧКОЙ ПЕРСОНАЖА в шапке файла. Модель ImageFX/Nano Banana НЕ подхватывает карточку из шапки — она читает только текущий промпт. Если в карточке Персефоны-царицы написано «long wavy cream-and-lavender hair flowing down her back held by a tall ornate dark crown…», а в промпте сцены упомянута только «корона» и забыта «hair flowing down her back» — модель сгенерит лысую персонажку с короной на голом черепе. То же самое с одеждой, аксессуарами, цветом меха.

   **Чек-лист на каждый промпт:**
   - **Волосы** — ДОЛЖНЫ быть упомянуты явно в каждой сцене где видна голова персонажа («long wavy cream-and-lavender hair flowing down her back»), НЕ полагаться на упоминание короны/венка. Если корона/crown/wreath упоминается — рядом обязательно «her hair flowing down her back held by [crown]» или «her hair … under [wreath]».
   - **Одежда** — полное описание из карточки (цвет, ткань, вышивка, пояс, сандалии). Не сокращать до «in her gown».
   - **Антропоморфность** — каждое появление персонажа сопровождается «bipedal humanoid body proportions body upright not on four legs». Без этого в action-сценах модель скатывается в реалистичную четвероногую кошку.
   - **Голые части** — не оставлять `her ankle`/`her hand`/`her arm` без `humanoid` рядом, иначе получится человеческая нога/рука вместо кошачьей.
   - **Маркер сцены уникален** — первые 3–4 английских слова промпта не повторяются между сценами файла.

   Быстрая проверка: `grep -n "Persephone\|Hades\|Demeter" content/<миф>/prompts/images.md | grep -v "hair"` — все строки персонажей где НЕ упомянуты волосы. Если есть совпадения и в этой сцене видна голова — добавить описание волос.

   **После генерации — визуальная сверка картинок с карточками:**
   Открыть в webapp каждую сцену в режиме image и сверить ВСЕХ персонажей в кадре с их карточкой в `images.md`. Типичные расхождения, которые надо отлавливать ДО генерации видео (потому что Veo возьмёт картинку как есть и доработает дефект ещё больше):
   - **Волосы пропали** — самая частая ошибка, видна сразу. Лысая голова под короной/венком = промпт сцены забыл `hair flowing…`.
   - **Цвет меха/глаз поплыл** — проверить, что Persephone-maiden в сцене 3 и Persephone-queen в сцене 21 это явно ОДИН персонаж (тот же `pale-lavender-and-cream calico, violet eyes`).
   - **Одежда потеряла детали** — вышивка пропала, цвет упростился, исчезли украшения из карточки.
   - **Превращение в реалистичную кошку** — особенно в action-кадрах (бег, прыжок, падение). Лечится через `bipedal upright on two legs` в промпте + ре-генерация.
   - **Поза не соответствует тексту** — например, текст «упала», а на картинке стоит. Re-prompt или ручная re-roll в Flow.

   Если картинка не подходит — править промпт в `images.md` (а не только перегенерить раз в Flow), чтобы при повторном прогоне баг не вернулся. После правок в одной сцене — пробежать глазами по тем же местам в остальных сценах с этим персонажем (волосы пропадают системно).

8. **Стикеры — придумываем 4-6 штук.** После того как картинки апрувнуты (шаг 7), Claude **предлагает 4-6 стикеров под конкретные сцены, начиная со сцены 2**. Стикеры должны быть слегка юморными, прикольными или подмигивающими — в духе мемного оверлея, который усиливает шутку или пуант сцены. Эталон — **«Свадебный договор» в Персефоне и Аид** (всплывает на сцене 23.28–24.78s, когда Аид «без сватов и записок» делает её женой — pixel-art свиток с лапками и печатями подсвечивает абсурдность ситуации).

   Claude предлагает в формате таблицы: «сцена N → идея стикера → 1-2 предложения почему этот момент». Я выбираю сколько и какие, или прошу переделать. После аппрува Claude пишет **`content/<Название мифа>/prompts/stickers.md`** — отдельный файл промптов рядом с `images.md` / `video.md` / `voiceover.md`. Формат — как у `images.md`: блоки `## Сцена N` с одной строкой `**Промпт:**` внутри и **уникальным subject-маркером** в первых 3-4 английских словах. Маркер — короткая фраза, которая попадёт в имя файла из Flow (например `cat goddess marriage order` → `Cat_goddess_marriage_order_<дата>.jpeg`).

   Правила промптов стикеров:
   - **Прозрачный фон** — обязательно: `transparent background, isolated, no scene background, no environment` + явно negativе `no scene, no setting, no landscape`.
   - **Pixel-art стиль канала** — тот же `highly detailed pixel art, modern detailed pixel art style`.
   - **Без текста и подписей внутри стикера** — `no text, no letters, no captions` (модель часто хочет приклеить надпись).
   - **Один объект в кадре** — стикер визуально читается за 0.5 секунды.
   - **Юмор/абсурд** заложен в самой идее, не в стиле — стиль остаётся консистентным с роликом.

9. **Генерация стикеров в Flow + раскладка скриптом.** Я открываю Flow, через расширение BOGI Promptr копирую промпты из `stickers.md`, генерирую и скачиваю все стикеры одним архивом. Дальше скрипт распределяет архив по папке стикеров и переименовывает каждый файл в `scene_<NN>_<маркер>.<ext>`:

   ```bash
   python automation/distribute_stickers.py "content/<миф>/images/stickers/<archive>.zip"
   # сухой прогон → план раскладки. Если устраивает — добавить --execute:
   python automation/distribute_stickers.py "content/<миф>/images/stickers/<archive>.zip" --execute
   ```

## Правила написания сценариев

- Длина: история за ~1 минуту (около 150–200 слов)
- Язык: живой, разговорный русский — без канцелярита и ИИ-шаблонов
- Структура: крючок в первой фразе → развитие событий → неожиданный или эмоциональный финал
- Тон: лёгкий, с иронией, но уважительный к мифу
- Имена: греческое написание (Прометей, Эпиметей, Гефест, Зевс и т.д.)

### Кликбейтный хук ДО интро (ОБЯЗАТЕЛЕН)

Каждый `prompts/voiceover.md` строится по жёсткому шаблону:

```

<КЛИКБЕЙТНЫЙ ХУК — 1–2 предложения, удерживают зрителя в первые 3 секунды>

<Имя/Название>. Миф за минуту.

<основной текст истории, ~150–200 слов>
```

Порядок жёсткий: **сначала хук, потом интро «<...>. Миф за минуту.», потом основной текст**. Если первой строкой звучит «Персефона и Аид. Миф за минуту.» — зритель ещё не понимает, зачем смотреть, и свайпает к 2-й секунде. Поэтому первым же кадром должна звучать ставка/крючок, а уже после — титульная плашка мифа. Эталон — Персефона и Аид:

```
Её украл владыка мёртвых — и мир впервые увидел зиму.

Персефо́на и Аи́д. Миф за минуту.
```

Что даёт «Её украл владыка мёртвых — и мир впервые увидел зиму» в первые 3 секунды:

- сразу даёт мощный конфликт (похищение) и масштаб (происхождение зимы) — зритель не успевает свайпнуть
- титул мифа звучит уже после крючка — к этому моменту человек уже зацепился и хочет узнать, как именно
- такой порядок повторяет приём, который автор канала уже руками собрал в CapCut для «Персефоны и Аида» — и он работает

Шаблоны хуков под разные мифы:

- **Ставка-сюрприз:** «Представьте: <желанная сила>. <Герой> думал — это <позитив>. Оказалось — <ловушка>.» (Мидас, Прометей)
- **Ставка-ужас:** «Каждые <X> лет <страна> отправляла <жертв> на верную гибель. Назад не возвращался никто.» (Тесей, Минотавр)
- **Невозможный вопрос:** «Что если <сделать невозможное>? Один <герой> попытался — и <последствие>.» (Сизиф, Орфей)
- **Невероятная клятва:** «Один <бог> поклялся <обещание>. И сдержал слово, не подумав о последствиях.» (Аполлон+Кассандра, Зевс+Семела)
- **Сразу-конфликт:** «Её украл владыка мёртвых — и мир впервые увидел зиму.» (Персефона и Аид)

Хук и интро **озвучиваются и монтируются как одна сцена** (sentence_001 = хук, sentence_002 = «<Миф>. Миф за минуту.», но визуально это один блок «титул-сцены» с нарастающим караоке-текстом мифа поверх кадра-крючка — так это уже сделано вручную в CapCut-драфте «Персефона и Аид»). При разбивке `voiceover.md` на `voiceover/texts/sentence_NNN.txt` хук ОБЯЗАН быть отдельным файлом и идти **первым** — под него монтажёр кладёт самую сильную картинку первой сцены, а титул мифа поверх неё накапливается караоке-блоком.

Шаблон с напоминанием про хук автоматически создаётся при «+ Новый миф» в webapp (см. раздел «Создание сценария через UI»).

## Персонажи (ЖЁСТКИЕ правила, применяются ко ВСЕМ сценариям)

1. **Все герои — антропоморфные бипедальные коты.** Не настоящие четвероногие кошки. Стоят, ходят, сидят, летают, жестикулируют как люди. Используют лапы как человеческие руки. Человеческие пропорции тела.
   - В каждом промпте обязательно: `anthropomorphic bipedal cat character, standing upright on two legs like a human, humanoid body proportions`

2. **В кадре НИКОГДА нет людей.** Ни на переднем плане, ни в толпе, ни как силуэты на фоне.
   - В каждом промпте обязательно негатив: `NO humans, NO people`

3. **В кадре НИКОГДА нет настоящих четвероногих кошек.** Модель без явного запрета часто рисует обычных кошек — особенно в сценах прыжков, полёта, бега.
   - В каждом промпте обязательно негатив: `NO real four-legged cats, only anthropomorphic bipedal cat characters`

4. **Консистентность персонажей внутри сценария.** Один и тот же герой во всех 25 сценах должен выглядеть одинаково — тот же окрас, возраст, борода, одежда, цвет глаз. Для каждого сценария в начале `scripts/*.md` заводится блок «карточка персонажей» в HTML-комментарии, и описание копируется в каждый промпт дословно. Нельзя писать «молодой кот» в одной сцене и «старый с бородой» в другой.

5. **Динамичные сцены — критическая зона.** Прыжки, полёт, бег, падения — именно там модель скатывается в «настоящих кошек на четвереньках». В таких промптах отдельно прописывать позу тела:
   - Прыжок: `human-like diving pose with arms outstretched, body upright not on four legs`
   - Полёт: `gliding pose like Superman with arms forward, body horizontal, humanoid posture`
   - Падение/паника: `humanoid body flailing arms, human-like gestures`

**Почему правила такие:** генерация icarus.md (первая версия) показала три типичных сбоя:

- (а) Дедал мутировал между сценами — в одной старик с бородой, в другой молодой кот
- (б) в сценах 8/17/19/20/21 герои были нарисованы как настоящие кошки на четырёх лапах
- (в) в сценах 13/14/16/19 модель добавила людей в кадр

Все три проблемы лечатся только явными формулировками в тексте каждого промпта — модель не помнит, что было в предыдущей сцене.

## Длина видео и структура сцен

- **Длина финального видео: 1:00–1:10** (YouTube Shorts / TikTok / Reels)
- На каждый сценарий — **20–25 коротких сцен по 2–4 секунды**. Одна сцена = одна анимация.
- Закадровый текст сцены — 7–10 слов (≈2–4 сек озвучки)
- Короткие сцены = высокая смена кадров = хорошее удержание зрителя. Длинные статичные сцены убивают ретеншн.

## Связка озвучки и видео (вариант A — принят 2026-04-20)

**Правило:** одно предложение озвучки = одна «сцена». Внутри сцены может быть несколько визуальных шотов для динамики. Маппинг — через имя файла, без ручных таблиц и ffmpeg-склеек.

**Именование файлов:**

- Озвучка: `sentence_NN.mp3` (один TTS-запрос на целое предложение — интонация сохраняется). В `approved_sentences/` файлы могут быть `sentence_NNN_vX.mp3` после ручного выбора лучшего варианта — при рендеринге переименовать в `sentence_NN.mp3`.
- Видео: `scene_NN_M.mp4`, где `NN` — номер предложения (совпадает с `sentence_NN`), `M` — индекс шота (`01`, `02`, `03`...).
  - Короткое предложение → один шот: `scene_05_01.mp4`.
  - Длинное предложение → несколько шотов для ритма: `scene_09_01.mp4`, `scene_09_02.mp4`, `scene_09_03.mp4`.

**Сцена в pyCapCut (`scene_structure_<миф>.py`):**

```python
Scene(
    sid="NN",
    audios=["sentence_NN.mp3"],
    videos=[VideoShot(file="scene_NN_01.mp4"), VideoShot(file="scene_NN_02.mp4")],
    text="Субтитры сцены",
    transition_after="Прыжок и отскок",
)
```

Длительность сцены = длительность аудио. Шоты делят это время поровну.

**Частые ошибки:**

- НЕ размазывать одно предложение на две отдельные сцены с отдельными аудио. Если нужна визуальная смена — делай шоты `_01/_02` внутри одной сцены.
- НЕ класть два предложения в один `scene_NN`. Если для двух коротких фраз хочется единый визуал («Заново. Навсегда.»), склей их в одно предложение в `voiceover.md` — ElevenLabs нормально тянет две точки в одном запросе. Интонация ломается только внутри *незакрытого* предложения.
- НЕ делать ffmpeg-concat на аудио. При этой схеме склейки не нужны.

## Визуальное разнообразие (важно!)

- **НЕ повторять одни и те же объекты** из сцены в сцену (вазы с кошками + статуи с кошками в каждом кадре — плохо).
- Варьировать окружение по ходу истории: греческие корабли (триремы), оливковые рощи, морские пейзажи, интерьеры мастерских, крепости, башни, храмы, рынки, пастухи, дельфины, чайки, облака, закаты, рассветы, пещеры, костры, свечи, факелы, масляные лампы.
- Разные ракурсы и планы: крупный план, средний, общий, вид сверху, от первого лица, низкий ракурс.
- Разное освещение: утро/полдень/закат/ночь/огонь/луна.
- **Кошачьи декоративные мотивы** (статуи котов, вазы с котами, фрески с котами) — уместны в **дворцах и храмах**, но НЕ в природных, производственных, морских сценах. В мастерской, на корабле, на скале — обычный греческий антураж без принудительных кошачьих деталей. Главные герои — всегда коты, но декор вокруг — по контексту.

## Уникальный subject-маркер в начале каждого промпта

**Правило:** первые 3–4 слова каждого `**Промпт:**` в `prompts/images.md` и `prompts/video.md` — это короткая английская фраза-действие, **уникальная между всеми сценами одного сценария**. Только потом идёт стилевой каркас.

**Пример:**

```
**Промпт:** persephone gathering spring flowers, highly detailed pixel art, 9:16 vertical, idyllic medium-wide shot...
**Промпт:** demeter torch night search, highly detailed pixel art, 9:16 vertical, sweeping cinematic wide shot...
**Промпт:** hades scooping persephone meadow, highly detailed pixel art, 9:16 vertical, dynamic medium shot...
```

**Зачем:** Google Flow / ImageFX берут первые слова промпта в имя экспортируемого файла (`Persephone_gathering_spring_flowers_<date>.jpeg`). Если префиксы уникальны — раскладка экспортированного архива по `scene_NN/vN.jpg` становится **тривиальной** (один pattern-matching без визуальной сверки). Если префиксы повторяются — архив превращается в кашу, в которой 12 файлов с одним именем покрывают 3 разные сцены и приходится открывать каждую картинку и сличать с промптом.

**Когда применять:** ВСЕГДА при написании `prompts/images.md` и `prompts/video.md` для нового сценария. Особенно критично если планируется **ручная** генерация в Flow (минуя `imagefx_runner.py` / `video_runner.py`).

**Как формулировать маркер:**

- 3–4 английских слова, описывающих что в кадре (`hades scooping persephone meadow`, `frozen river winter valley`, `pomegranate seed binding magic`)
- Не должен совпадать с маркерами других сцен — даже частично; избегать одинакового первого слова там, где можно (если первое слово неизбежно повторяется — `persephone …`, `hades …` — то 2-е и 3-е должны различаться)
- Маркер сам по себе должен быть **валидным описанием сцены**, потому что он попадает в начало промпта и слегка влияет на генерацию

**Проверка перед запуском раннера/Flow:**

```bash
grep '^\*\*Промпт:\*\* ' prompts/images.md \
  | sed -E 's/^\*\*Промпт:\*\* ([^,]+),.*/\1/' \
  | sort | uniq -c | sort -rn
```

Все строки должны быть с числом `1`. Если есть `2` или больше — переписать дубликат.

## Ограничения платформ (TikTok / YouTube Shorts)

Тематика греческих мифов часто задевает «триггерные» слова модерации. Правила ниже применять ко **всем** сценариям — к озвучке, субтитрам, промптам картинок и видео.

### Слова-триггеры в озвучке и субтитрах

TikTok распознаёт речь и ловит стоп-слова даже в аудио. YouTube мягче, но при прямых формулировках может снизить охваты Shorts или поставить возрастное ограничение (18+) — для коротких форматов это почти смерть ролика.

**Заменять:**

| Вместо | Использовать |
|---|---|
| убил / убивает | сразил, одолел, поверг, сокрушил |
| смерть | конец, гибель, уход, исчезновение |
| умер / погиб | пал, сгинул, не стало, покинул мир |
| труп | тело, поверженный |
| кровь | — (не упоминать в тексте) |
| самоубийство, повесился и т.п. | — (полностью переформулировать сцену) |

Контекст мифологии/истории/образования смягчает модерацию на YouTube, но TikTok-бот контекст не читает — поэтому пишем мягче по умолчанию.

### Визуальные ограничения (промпты картинок и видео)

Pixel art стиль сам по себе снижает риски (мультяшность), но прямые сцены насилия всё равно ловятся:

- **Кровь, красные брызги, раны** — не включать в промпты, добавлять в негатив: `no blood, no gore, no wounds`
- **Отрубленные головы, расчленение** — показывать как силуэт в мешке, тень, закадровый намёк. Голова Медузы — мешок/тень, не сам артефакт крупным планом
- **Момент удара / гибели** — не добивание в кадре. Только: вспышка, силуэт поверженного, падение, растворение в тени, затемнение
- **Исчезновение персонажа** (Эвридика, превращения) — мягкое растворение, частицы, туман, без агонии

### Приоритет сценариев по безопасности охватов

- **Самые безопасные:** Мидас (нет насилия), Арахна (превращение, без смерти), Нарцисс
- **Средний риск:** Орфей и Эвридика (эмоционально, но без резни), Персефона
- **Требуют аккуратной подачи:** Персей (Медуза), Тесей (Минотавр), Геракл (чудовища)

## IP-фильтр Veo: имена греческих богов в `prompts/video.md`

Veo 3.1 (через Google Flow) **отказывается генерировать видео** с ошибкой:

> `I can't generate the video you requested right now due to interests of third-party content providers. Please edit your prompt and try again.`

когда в промпте упоминаются имена греческих богов / героев, которые также являются названиями популярных видеоигр / фильмов / IP. Самые горячие триггеры — `Hades` (популярная игра Supergiant Games), `Persephone`, `Zeus`, `Athena` (фигурируют в «God of War», «Hi-Fi Rush», «Hades II» и др.). На сценах 17/18/19/20 Орфея именно эти имена отстреливали генерацию — после descriptive-замены прошло.

**Правило:** в `prompts/video.md` для **всех** сцен заменять собственные имена на descriptive-фразы. В `prompts/images.md` имена **можно оставлять** — там фильтр Flow/ImageFX другой и работает мягче.

Таблица замен:

| Имя (видео — ПЛОХО) | Descriptive замена (видео — ОК) |
|---|---|
| `Hades` | `the somber dark-charcoal-gray regal cat king` |
| `Persephone` / `Persephone's place` | `the calico queen` / `the smaller paler empty consort throne` |
| `Zeus` | `the throned thunder cat king` |
| `Athena` | `the silver-grey-and-white wisdom cat goddess` |
| `Apollo` | `the golden sun cat archer` |
| `Orpheus` | `the slender musician cat character` |
| `Eurydice` | `the calico bride cat character` |
| `Cerberus` | `the massive three-headed feline guardian` |
| `Charon` | `the gaunt cloaked ferryman cat character` |
| `Persephone`, `Hera`, `Aphrodite`, `Artemis`, `Ares`, `Poseidon` | descriptive по образцу выше |

Также превентивно:

- `lord of the underworld` → `regal cat king`
- `underworld` → `shadowy hall` / `dark-stone columned hall` / `dark corridor`
- `scepter` → `ceremonial staff` (более нейтрально, не royal-IP-нагружено)

В блоке `**Звуки:**` тоже переименовывать (например `Hades's wordless low sigh` → `regal cat king's wordless low sigh`).

**Картинка-вход (image-to-video) при этом не меняется** — визуал персонажа полностью берётся из неё (корона, скипетр, тронный зал, узнаваемое лицо), а текст-промпт описывает только движение нейтральными словами. Поэтому подменa в video.md не ломает консистентность с уже одобренной картинкой.

## Озвучка (TTS через ElevenLabs)

**Сервис:** <https://elevenlabs.io/app/speech-synthesis/text-to-speech>

### Правила озвучки

1. **Озвучка идёт по предложениям, не по частям.** Если разбить одно предложение на два TTS-запроса, интонация в середине фразы ломается — ElevenLabs не знает, что предложение продолжается. Минимальная единица — полное предложение с точкой/восклицательным/вопросительным знаком.

   **Исключение — интро.** Титульная строка сценария («Сизи́ф. Миф за минуту.», «Ика́р и Деда́л. Миф за минуту.» и т.п.) озвучивается ОДНИМ запросом — два коротких предложения, но читаются как единая титульная фраза. Эта строка **больше не первая** в `voiceover.md` — перед ней идёт кликбейтный хук (см. раздел «Кликбейтный хук ДО интро»). При разбивке на `sentence_NNN.txt` хук становится `sentence_001`, а титул — `sentence_002`.

2. **На каждое предложение — 3 варианта озвучки.** После Generate нажимаем Regenerate ещё 2 раза → получаем 3 mp3. На бесплатном тарифе ElevenLabs 3 варианта бесплатно, 4-й уже платный — не генерируем больше. Потом вручную выбираем лучший.

3. **Связь «предложение ↔ сцена» не 1:1.** В `voiceover.md` предложения могут:
   - совпадать со сценой (`сцена_03.mp3` = одно предложение),
   - содержать несколько сцен (одно длинное предложение покрывает `сцена_04` + `сцена_05`),
   - одна сцена может состоять из нескольких предложений (`сцена_18_01.mp3`, `сцена_18_02.mp3`).

4. **Структура папок:** каждое предложение хранится в своей подпапке со всеми 3 вариантами:

   ```
   content/<Название мифа>/voiceover/audio/
   ├── sentence_001/
   │   ├── sentence_001_v1.mp3
   │   ├── sentence_001_v2.mp3
   │   └── sentence_001_v3.mp3
   └── sentence_002/
       └── ...
   ```

   После выбора лучшего варианта вручную переименовать в `scene_NN.mp3` / `scene_NN_XX.mp3`.

5. **Ударения в тексте** (`Ика́р`, `Деда́л`, `Сизи́ф` и т.д.) вставляются прямо в поле ввода ElevenLabs — модель их правильно интерпретирует.

### Процесс

1. Скрипт `automation/elevenlabs_runner.py` читает `content/<Название мифа>/prompts/voiceover.md`, разбивает текст на предложения.
2. Для каждого предложения: открывает форму → вставляет текст → жмёт Generate → ждёт генерации → скачивает mp3.
3. Файлы складываются в `content/<Название мифа>/voiceover/audio/` с именами `sentence_001.mp3`, `sentence_002.mp3`, ...
4. **Ручной шаг:** пересопоставить предложения со сценами и переименовать в `scene_NN.mp3`.

## Инструкция по гуманизации текста

При написании и редактировании сценариев избегать:

- Канцелярита: «в рамках», «осуществлять», «данный», «является»
- ИИ-клише: «стоит отметить», «важно подчеркнуть», «нельзя не упомянуть»
- Раздувания значимости: «ключевой», «непреходящий», «знаковый»
- Списков с жирными заголовками там, где уместен живой текст
- Шаблонных концовок: «будущее выглядит многообещающим» и т.п.
- Подхалимского тона и артефактов чатбота

Добавлять:

- Живой ритм: чередовать короткие и длинные предложения
- Конкретику вместо абстракций
- Иронию и характер там, где уместно
- Русские кавычки «ёлочки», не английские "..."
